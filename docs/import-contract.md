# Контракт импорта

Документ будет уточняться вместе с реализацией. На текущем этапе зафиксировано:

- обрабатывается активный лист XLSX;
- полностью пустые строки игнорируются;
- частично заполненные или невалидные строки считаются ошибочными;
- обязательные заголовки могут находиться в любом порядке;
- дополнительные колонки не участвуют в импорте;
- одна ошибочная строка не останавливает весь импорт;
- существующие данные не перезаписываются при повторном `external_id`.

Все пять значений обязательны. `external_id` хранится как регистрозависимая
строка, `user_id` — как неотрицательное целое число, а `email` проходит
стандартную проверку Django.

При чтении применяются следующие преобразования:

- целочисленный `external_id` преобразуется в строку;
- `user_id` принимается как целое число, целочисленное значение Excel или
  строка из ASCII-цифр;
- внешние пробелы удаляются у `external_id`, `email` и `subject`;
- исходное форматирование `message` сохраняется, но строка только из пробелов
  считается невалидной;
- логические значения и дробные идентификаторы отклоняются.

Workbook открывается с параметрами `read_only=True` и `data_only=True`. Формулы
не вычисляются: используется сохранённое в XLSX значение.

Команда должна отдельно сообщать результаты импорта и доставки, чтобы созданная
запись с ошибкой отправки не считалась невалидной строкой XLSX.
