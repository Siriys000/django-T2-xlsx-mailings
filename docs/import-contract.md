# Контракт импорта

Команда использует следующий контракт:

- обрабатывается активный лист XLSX;
- полностью пустые строки игнорируются;
- частично заполненные или невалидные строки считаются ошибочными;
- обязательные заголовки могут находиться в любом порядке;
- дополнительные колонки не участвуют в импорте;
- одна ошибочная строка не останавливает весь импорт;
- существующие данные не перезаписываются при повторном `external_id`.

Все пять значений обязательны. `external_id` хранится как регистрозависимая
строка, `user_id` — как неотрицательное целое число, а `email` проходит
стандартную проверку Django.

При чтении применяются следующие преобразования:

- целочисленный `external_id` преобразуется в строку;
- `user_id` принимается как целое число, целочисленное значение Excel или
  строка из ASCII-цифр;
- внешние пробелы удаляются у `external_id`, `email` и `subject`;
- исходное форматирование `message` сохраняется, но строка только из пробелов
  считается невалидной;
- логические значения и дробные идентификаторы отклоняются.

Workbook открывается с параметрами `read_only=True` и `data_only=True`. Формулы
не вычисляются: используется сохранённое в XLSX значение.

Идентификаторы с ведущими нулями и числовые идентификаторы длиннее 15 цифр
следует хранить в Excel как текст. Иначе Excel может изменить формат или
потерять точность ещё до запуска импорта, и восстановить исходное значение
будет невозможно.

## Результат импорта

Команда запускается с единственным обязательным аргументом — путём к файлу:

```bash
python manage.py import_mailings path/to/mailings.xlsx
```

Каждая корректная строка сохраняется через `get_or_create`. Если нормализованный
`external_id` уже существует, строка считается пропущенной, а сохранённые поля
не сравниваются и не обновляются. Валидация всей строки выполняется до проверки
дубликата, поэтому некорректный повтор учитывается как ошибка, а не как пропуск.

Новые записи накапливаются пакетами не более 100 сообщений. Каждый полный пакет
отправляется во время чтения файла, а последний неполный — после окончания
импорта. Внутри пакета используется не более четырёх worker-потоков. Для
пропущенных и невалидных строк функция отправки не вызывается.

Имитация отправки ждёт случайное число секунд в диапазоне 5–20, а затем пишет в
лог `external_id`. Email, тема и тело письма в сообщение лога не включаются.
Неуспешная попытка повторяется до общего лимита в три попытки. В лог и БД
записывается только класс исключения, но не потенциально чувствительный текст.

Итог содержит восемь счётчиков:

- `processed` — все непустые строки данных;
- `created` — созданные записи;
- `skipped` — корректные строки с существующим `external_id`;
- `errors` — строки, не прошедшие валидацию;
- `sent` — сообщения, успешно отправленные в текущем запуске;
- `send_failed` — сообщения, исчерпавшие попытки в текущем запуске;
- `attempts` — все вызовы функции отправки;
- `retries` — повторные вызовы после первой попытки.

Для завершившейся команды выполняется `created = sent + send_failed`. Поле
`delivery_attempts` хранит накопительное число попыток за все запуски, тогда как
итог команды описывает только текущий запуск.

Для завершившегося импорта выполняется:

```text
processed = created + skipped + errors
```

Ошибки строк выводятся в `stderr` с номером строки без полного содержимого
письма. Ошибка формата, структуры или ленивого чтения файла преобразуется в
`CommandError` и завершает команду с ненулевым кодом. Поскольку весь импорт не
обёрнут в общую транзакцию, корректные строки, обработанные до поздней ошибки
чтения, остаются сохранёнными и безопасно пропускаются при повторном запуске.
Сообщения из последнего ещё не отправленного пакета остаются в состоянии
`pending`. Неожиданные ошибки БД не маскируются под ошибки строк.

## Повторная доставка

Команда `python manage.py retry_mailings` выбирает `pending` и `failed`
сообщения пакетами по возрастанию первичного ключа. Успешно отправленные записи
получают состояние `sent` и `sent_at`; исчерпавшие попытки остаются `failed` и
могут быть обработаны следующим запуском. Записи со статусом `sent` повторно не
отправляются.
