# Архитектура и ограничения

## Импорт и идемпотентность

XLSX читается потоково, а письма отправляются последовательно. Вместе с SQLite
это обеспечивает простой локальный запуск без внешней инфраструктуры, но
обработка большого числа писем остаётся длительной из-за обязательной задержки.

Уникальное ограничение `external_id` и `get_or_create` предотвращают повторное
создание даже при гонке между проверкой и записью. Существующее сообщение не
обновляется: ТЗ определяет идемпотентность импорта, но не версионирование данных.

Общей транзакции на файл нет. Каждая строка фиксируется отдельно, поэтому сбой
не откатывает уже обработанные данные и не удерживает длительную транзакцию;
повторный запуск безопасно пропускает сохранённые строки. `bulk_create` не
используется, поскольку усложнил бы переносимый подсчёт созданных и пропущенных
записей без существенной пользы для последовательной отправки.

## Доставка

Границы обязательной задержки 5–20 секунд заданы именованными константами, а не
настройками окружения: отдельный конфигурационный контур заданию не требуется.
Для завершившейся команды `created` равно числу завершившихся вызовов отправки.

Запись сохраняется до отправки. При ошибке команда завершается без итоговой
статистики, запись остаётся в БД, а повторный импорт пропускает её. Поэтому
`external_id` гарантирует идемпотентность создания, но не exactly-once доставку.
Устранение этого окна потребовало бы статусов, повторных попыток или
transactional outbox — отдельного жизненного цикла, не требуемого в `main`.

## Расширенный вариант

Ветка
[`feature/extended-delivery`](https://github.com/Siriys000/django-T2-xlsx-mailings/tree/feature/extended-delivery)
добавляет состояния, повторные попытки и ограниченную параллельную отправку.
Celery и брокер сообщений не используются: для демонстрационного расширения их
инфраструктурная цена выше получаемой пользы.

## Настройки Django

Текущий `config/settings.py` предназначен для локального запуска management
command: используется SQLite, development `SECRET_KEY`, `DEBUG=True` и пустой
`ALLOWED_HOSTS`. Эти значения не являются секретами окружения и не подходят для
публикации веб-приложения. При реальном deployment потребовалось бы передавать
секрет, debug-флаг и список хостов из окружения, а также настроить HTTPS.
