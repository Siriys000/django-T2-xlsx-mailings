# Импорт рассылок из XLSX

[![CI](https://github.com/Siriys000/django-T2-xlsx-mailings/actions/workflows/ci.yml/badge.svg)](https://github.com/Siriys000/django-T2-xlsx-mailings/actions/workflows/ci.yml)

Django-приложение для импорта и отправки рассылок из XLSX-файлов.

Каждая строка файла описывает отдельное письмо. Импорт запускается через Django
management command, а `external_id` используется как ключ идемпотентности.

> Ветка `codex/extended-delivery` демонстрирует расширенный вариант со статусами
> доставки, повторными попытками и ограниченной параллельной отправкой. Буквальное
> решение задания остаётся в ветке `main`.

## Возможности

Management command потоково читает активный лист XLSX, валидирует и
идемпотентно сохраняет строки, после чего пакетами имитирует параллельную
отправку новых писем. Ошибка отдельной строки или доставки не прерывает
обработку файла.

## Технологии

- Python 3.10+
- Django 5.2
- SQLite

## Локальный запуск

```bash
python -m venv .venv
```

Активация окружения в PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

В Linux и macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей и проверка проекта:

```bash
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
```

## Формат XLSX

Первая строка должна содержать заголовки:

| Колонка | Назначение |
| --- | --- |
| `external_id` | Уникальный идентификатор записи во внешней системе |
| `user_id` | Идентификатор пользователя |
| `email` | Email получателя |
| `subject` | Тема письма |
| `message` | Текст письма |

## Импорт

```bash
python manage.py import_mailings path/to/mailings.xlsx
```

Команда обрабатывает активный лист, сохраняет и отправляет новые корректные
строки и не изменяет записи, чей `external_id` уже существует. Ошибка отдельной
строки выводится в `stderr` и не останавливает импорт.

Пример итоговой статистики:

```text
Import completed: processed=10, created=7, skipped=2, errors=1, sent=6, send_failed=1, attempts=9, retries=2
```

Полностью пустые строки не входят в `processed`. Ошибка структуры или чтения
файла завершает команду с ненулевым кодом. Доставка выполняется пакетами до 100
сообщений в четырёх потоках. Для каждого сообщения допускается до трёх попыток;
итоговые состояния и число попыток сохраняются в БД.

Повторная доставка всех сообщений в состояниях `pending` и `failed` запускается
отдельно:

```bash
python manage.py retry_mailings
```

## Основные решения

- XLSX читается потоково, чтобы размер файла не определял потребление памяти.
- Уникальность `external_id` обеспечивается ограничением базы данных.
- Для существующего `external_id` сохранённые данные не обновляются.
- Некорректная строка не останавливает обработку остальных строк.
- Письма отправляются параллельно ограниченными пакетами без внешнего брокера.
- Отправка имитируется записью в лог с обязательной задержкой 5–20 секунд.
- Ошибки доставки сохраняются без содержимого письма и могут быть повторены
  отдельной командой.
- Очередь задач, межпроцессная координация и exactly-once доставка не заявлены.

Подробный контракт импорта описан в
[docs/import-contract.md](docs/import-contract.md), а осознанные ограничения и
альтернативы — в [docs/design-tradeoffs.md](docs/design-tradeoffs.md).

## Тесты

```bash
python -m pip install -r requirements-dev.txt
ruff check .
ruff format --check .
python manage.py test
```

Тестовые XLSX создаются во временных каталогах во время запуска и не хранятся
в репозитории. Эти же проверки, Django system checks, проверка миграций и
зависимостей автоматически выполняются в GitHub Actions на Python 3.10 и 3.12.
